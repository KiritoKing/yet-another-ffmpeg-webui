# 任务系统功能文档

## 概述

FFmpeg Easy 的任务系统提供了强大的任务管理、批处理和历史记录功能，让您可以更高效地处理多个视频文件。

## 主要功能

### 1. 任务历史记录

所有执行过的任务都会自动保存到浏览器的 IndexedDB 中，即使关闭页面也不会丢失。

**功能特性：**
- 📊 **统计信息**：查看总任务数、成功率、平均耗时等统计数据
- 🔍 **筛选功能**：按状态（已完成、失败、已中止）和时间（今天、一周、一月）筛选
- 📋 **详细信息**：查看每个任务的输入文件、输出文件、执行时间、命令参数
- ❌ **错误详情**：失败任务会显示详细的错误信息和恢复建议
- 🗑️ **清理功能**：手动删除单个任务或批量清理 30 天前的旧记录

**使用方法：**
1. 点击主界面的"历史"标签页
2. 使用筛选器查找特定任务
3. 点击任务卡片查看详细信息
4. 需要时可以复制命令参数用于重新执行

### 2. 批处理和队列管理

支持一次性上传多个文件并自动排队处理，提高工作效率。

**功能特性：**
- 📁 **批量上传**：拖拽或选择多个文件（最多 10 个）
- ⚙️ **并发控制**：设置同时处理的任务数量（1-4）
- 📊 **实时监控**：查看队列状态、正在执行的任务和总体进度
- ⏸️ **灵活控制**：随时开始、停止或清空队列
- 🚫 **退出保护**：处理过程中尝试关闭页面会弹出确认提示

**使用方法：**
1. 选择一个命令预设
2. 点击"队列"标签页
3. 使用批量上传组件添加多个文件
4. 配置并发数（建议使用 1-2 以避免内存问题）
5. 点击"开始处理"启动队列
6. 在队列面板中监控进度

### 3. 友好的错误处理

系统会自动识别常见错误并提供可读的解释和恢复建议。

**错误类型：**

**可恢复错误**（可以尝试修复后重试）：
- 文件格式无效
- 文件未找到
- 编码器不支持
- 参数不支持

**不可恢复错误**（需要重新加载 FFmpeg）：
- 内存不足
- WebAssembly 运行时错误

**错误示例：**

```
❌ 内存不足，无法处理当前文件

💡 建议：
1. 减小输入文件大小（建议 < 200MB）
2. 降低输出分辨率或码率
3. 使用 -c copy 模式避免重新编码
4. 关闭其他占用内存的标签页
5. 重新加载 FFmpeg 后再试

⚠️ 这是一个不可恢复的错误，建议重新加载 FFmpeg。
```

### 4. 文件名清理

自动处理中文字符、空格和特殊字符，避免 FFmpeg 处理失败。

**处理规则：**
- 中文字符：自动移除
- 空格：转换为下划线 `_`
- 特殊字符：移除不支持的字符
- 空文件名：使用时间戳 `file_timestamp`

**示例：**
- `我的视频 (1).mp4` → `_1_.mp4`
- `video file.mov` → `video_file.mov`
- `测试视频.mp4` → `file_1699999999.mp4`

系统会在上传时显示警告，告知文件名已被清理。

### 5. WebAssembly 兼容性检测

自动识别 WebAssembly 版本不支持的 FFmpeg 选项，提前警告用户。

**不支持的选项包括：**
- 硬件加速：`-hwaccel`, `-vaapi_device` 等
- 网络协议：`-rtsp_transport`, `-tcp` 等
- 设备输入：`-f dshow`, `-f avfoundation` 等

执行命令时如果检测到不支持的选项，会显示警告但仍允许执行（某些情况下可能成功）。

## 技术细节

### 数据持久化

- **IndexedDB**：使用 Dexie.js 管理任务历史记录
- **内存缓存**：当前会话的输出文件（Blob URLs）仅保存在内存中
- **自动清理**：页面关闭时自动释放所有 Blob URLs

### 队列处理

- **并发控制**：使用信号量模式控制并发任务数
- **错误隔离**：单个任务失败不影响其他任务
- **进度追踪**：每个任务独立追踪进度

### 安全性

- **文件保护**：所有处理完全在浏览器中进行，文件不会上传到服务器
- **内存管理**：自动检测内存使用，提前警告可能的内存问题
- **错误恢复**：严重错误时自动清理 FFmpeg 实例，防止状态污染

## 最佳实践

### 批处理建议

1. **控制文件大小**：
   - 重新编码任务：每个文件 < 200MB
   - 仅复制任务：每个文件 < 500MB

2. **合理设置并发数**：
   - 小文件（< 50MB）：可以使用 2-3 并发
   - 大文件（> 100MB）：建议使用 1 并发
   - 复杂编码（VP9、H.265）：必须使用 1 并发

3. **监控内存**：
   - 关注浏览器任务管理器
   - 如果内存接近上限，停止队列并重新加载页面

### 错误处理建议

1. **遇到可恢复错误**：
   - 按照建议修改参数或文件
   - 直接重试

2. **遇到不可恢复错误**：
   - 点击"重新加载 FFmpeg"
   - 减小文件大小或简化命令
   - 考虑分段处理

### 文件命名建议

1. **上传前重命名**：
   - 使用纯英文字母和数字
   - 避免空格，使用下划线或连字符
   - 保持文件名简短

2. **批量处理时**：
   - 使用统一的命名规则
   - 添加序号便于识别

## 常见问题

### Q: 任务历史记录会占用多少存储空间？

A: 每条记录约 1-2KB，即使保存 1000 条记录也只占用 1-2MB。系统会自动清理 30 天前的记录。

### Q: 队列处理失败会怎样？

A: 失败的任务会被记录，但不会影响其他任务。可以在历史记录中查看失败原因并单独重试。

### Q: 可以暂停队列处理吗？

A: 目前只支持停止整个队列，已执行的任务会完成，未开始的任务会保留在队列中。

### Q: 为什么建议并发数设置为 1？

A: WebAssembly 版本的 FFmpeg 内存限制较严格，多任务并发容易导致内存溢出。除非处理的都是小文件，否则建议使用 1。

### Q: 任务历史可以导出吗？

A: 目前不支持导出，但您可以在浏览器开发者工具中访问 IndexedDB 数据。未来版本会添加导出功能。
